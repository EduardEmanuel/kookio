# NX Guidelines

> **Status: Active (partial)** — NX v21 monorepo with `@nx/angular` and `@nx/js` generators is the established setup; `@kookio/*` import paths and dependency boundaries are in use. **Diverges**: the documented library-type taxonomy (`ui` / `data-access` / `util` / `types`) is not the actual lib organization — real layout is `core/{config,logging,security}`, `feature/{auth,shell}`, `prisma/client`, `server/{auth,logger,trpc}`, `shared/{mock,ui,utility}`. Treat the lib-type table as historical guidance, not enforced policy.

## Version

NX v21+

## Library Types

| Type          | Purpose                                        | Example                            |
| ------------- | ---------------------------------------------- | ---------------------------------- |
| `ui`          | Presentational components with no side effects | `ButtonComponent`, `CardComponent` |
| `data-access` | Stores, services, API clients                  | `UsersStore`, `UsersService`       |
| `util`        | Pure functions, pipes, helpers                 | `formatDate()`, `truncate pipe`    |
| `types`       | Shared TypeScript interfaces and types         | `User`, `ApiResponse<T>`           |

## Dependency Boundaries

- `ui` libs must NOT depend on `data-access` libs
- `data-access` libs may depend on `types` and `util` libs
- `util` libs must NOT depend on `data-access` or `ui` libs
- `types` libs must NOT depend on anything else
- Apps may depend on all lib types
- Enforce boundaries via NX `@nx/enforce-module-boundaries` lint rule

## Library Generation Templates

### JS/TS Library (logic, services, utils, types)

```bash
npx nx g @nx/js:lib <DIR_NAME-LIB_NAME> \
  --directory=libs/<DIR_NAME>/<LIB_NAME> \
  --importPath=@kookio/<DIR_NAME-LIB_NAME> \
  --bundler=tsc \
  --unitTestRunner=vitest \
  --linter=eslint \
  --no-interactive
```

### Angular Library (components, directives, pipes)

```bash
npx nx g @nx/angular:library \
  --directory=libs/<DIR_NAME>/<LIB_NAME> \
  --importPath=@kookio/<DIR_NAME-LIB_NAME> \
  --unitTestRunner=vitest \
  --linter=eslint \
  --style=scss \
  --standalone \
  --no-interactive
```

## Bundler Strategy

| Generator             | Bundler        | Reason                                                                |
| --------------------- | -------------- | --------------------------------------------------------------------- |
| `@nx/js:lib`          | `tsc`          | Correct type declarations, zero overhead, ideal for internal monorepo |
| `@nx/js:lib`          | `esbuild`      | Only for publishable libs or where bundle size matters                |
| `@nx/angular:library` | Vite (default) | Only supported bundler — does not accept `--bundler=tsc`              |

- Do not use `--bundler=tsc` with `@nx/angular:library` — it is ignored or causes errors
- Do not use `--buildable` if the library is only consumed internally within the monorepo

## Auto-Generated Targets

### `@nx/js:lib` with `--bundler=tsc`

| Target  | Executor                 | Notes |
| ------- | ------------------------ | ----- |
| `build` | `@nx/js:tsc`             | ✅    |
| `test`  | `@nx/vite:test` (vitest) | ✅    |
| `lint`  | `@nx/eslint:lint`        | ✅    |

### `@nx/angular:library` (without `--buildable`)

| Target       | Executor                 | Notes                                                                        |
| ------------ | ------------------------ | ---------------------------------------------------------------------------- |
| `build-deps` | `nx:noop`                | ⚠️ non-buildable — consumed directly via TS paths                            |
| `typecheck`  | `tsc --noEmit`           | ✅ cacheable                                                                 |
| `test`       | `@nx/vite:test` (vitest) | ✅ cacheable — **must be added manually, not generated automatically by NX** |
| `lint`       | `@nx/eslint:lint`        | ✅ cacheable                                                                 |
| `watch-deps` | continuous               | ✅ useful in dev                                                             |

## Gotcha: `vite:test` vs `test`

`@nx/angular:library` generates the test target with the name `vite:test`, not `test`.

```bash
nx run ui:vite:test   # ✅ correct
nx run ui:test        # ❌ does not exist
```

When running tests with `nx run-many -t test`, Angular libraries **will be silently skipped**
(no errors). This behavior is acceptable for an internal monorepo.

For consistency, add an alias in `project.json`:

```json
"targets": {
  "test": {
    "executor": "@nx/vite:test"
  }
}
```

## Key Differences Between Generators

| Aspect                    | `@nx/js:lib`       | `@nx/angular:library` |
| ------------------------- | ------------------ | --------------------- |
| Angular components        | ❌                 | ✅                    |
| Recommended bundler       | `tsc` or `esbuild` | Vite (default)        |
| Test target name          | `test`             | `vite:test`           |
| `--bundler=tsc` supported | ✅                 | ❌                    |
| Standalone components     | N/A                | `--standalone`        |
| SCSS                      | N/A                | `--style=scss`        |

## When to Use Which Generator

| Library content                       | Generator             |
| ------------------------------------- | --------------------- |
| Angular components, directives, pipes | `@nx/angular:library` |
| Services, stores, API clients         | `@nx/js:lib`          |
| Pure functions, helpers, TS pipes     | `@nx/js:lib`          |
| TypeScript interfaces and types       | `@nx/js:lib`          |

## General Rules

- Always use `--no-interactive` for reproducibility in CI
- Import libraries via `@kookio/<lib-name>` — never via deep relative paths
- Enforce dependency boundaries defined in `nx.json` with `@nx/enforce-module-boundaries`
- Run `nx run-many -t lint typecheck` before any PR
